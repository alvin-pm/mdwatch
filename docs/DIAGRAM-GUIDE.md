# ASCII 다이어그램 작성 가이드 — 깨지지 않는 박스 그리기

md 코드블록 안에 텍스트 다이어그램(박스·플로우)을 그릴 때 브라우저에서 정렬이 깨지지 않게 하는 규칙입니다. **사람이 쓸 때도, AI 에이전트가 생성할 때도 동일하게 적용하세요.** (AI용 복붙 지시문은 [맨 아래](#ai-에이전트용-지시문-복붙용))

## 왜 깨지는가

두 가지 독립적인 원인이 있고, 둘 다 잡아야 합니다.

**원인 1 — 모호폭(East Asian Ambiguous) 문자.**
박스 문자(`┌ ─ │ └ ┘`), 화살표(`→ ← ► ◄ ↑ ↓`), 원문자(`① ②`), 기호(`× · ≥ ※`)는 유니코드 폭 분류가 "Ambiguous"입니다. 같은 고정폭 폰트라도 렌더러·플랫폼에 따라 1칸 또는 2칸으로 그려져서, **어떤 폰트를 써도 정렬을 보장할 수 없습니다.**

**원인 2 — 한글 폭이 영문의 정확히 2배가 아닌 폰트.**
일반 고정폭 폰트(SF Mono 등)에는 한글 글리프가 없어 비례폭 한글 폰트로 폴백되고, 그 폭은 영문 2칸과 미세하게 어긋납니다. mdwatch는 이를 위해 코드블록에 **D2Coding**(한글 폭 = 영문 폭 x 2 보장)을 1순위로 사용합니다 — [INSTALL.md 4-(4)](INSTALL.md) 참조.

## 규칙

### 규칙 1 — 확정폭 문자만 사용

| 쓰지 말 것 | 대신 쓸 것 |
|---|---|
| `┌ ─ ┐ │ └ ┘ ├ ┤` (박스 문자) | `+ - \|` |
| `→ ← ► ◄` (화살표) | `-> <- > <` |
| `↑ ↓` | `^ v` |
| `① ② ③` (원문자) | `(1) (2) (3)` |
| `×` | `x` |
| `≥ ≤` | `>= <=` |
| `·` (가운뎃점) | `.` 또는 `/` |
| `※` | `*` |

허용 문자는 **ASCII(1칸) + 한글(2칸)** 뿐입니다. 이 둘은 어디서나 폭이 확정적입니다.

### 규칙 2 — 폭 검증 필수, 크기 예외 없음

한글이 섞인 줄의 패딩을 눈대중이나 암산으로 맞추면 반드시 틀립니다. 3줄짜리 박스도 예외가 아닙니다 (실제로 아래 사례처럼 틀립니다):

```
잘못된 예 (1행 18칸, 2행 19칸, 3행 17칸 — 제각각):
+----- 박스 -----+
| 한글 정렬 유지  |
+---------------+

올바른 예 (전부 18칸):
+----- 박스 -----+
| 한글 정렬 유지 |
+----------------+
```

검증 스크립트 (Python):

```python
import unicodedata

def width(s):
    """표시 폭 계산: 한글(W/F)=2칸, ASCII=1칸. 모호폭(A) 문자는 에러."""
    total = 0
    for c in s:
        eaw = unicodedata.east_asian_width(c)
        assert eaw != 'A', f"모호폭 문자 사용됨: {c!r} ({hex(ord(c))}) — 규칙 1 위반"
        total += 2 if eaw in 'WF' else 1
    return total

# 박스의 모든 줄에 대해 width()가 동일해야 통과
lines = ["+----- 박스 -----+", "| 한글 정렬 유지 |", "+----------------+"]
assert len({width(l) for l in lines}) == 1, {l: width(l) for l in lines}
```

### 규칙 3 — 복잡한 정렬은 구조를 바꿔라

여러 열을 가로로 맞추는 표 형태 다이어그램은 오류 확률이 열 수에 비례해 커집니다. 4열 플로우를 억지로 맞추기보다 **세로 흐름**(단계별 한 줄 + `| v` 화살표)으로 재구성하는 것이 안정적이고 읽기도 좋습니다.

## AI 에이전트용 지시문 (복붙용)

Claude Code의 `CLAUDE.md`, Cursor rules 등 AI 설정 파일에 아래 블록을 붙여넣으면, AI가 생성하는 다이어그램이 mdwatch에서 깨지지 않습니다:

```text
md 코드블록에 ASCII 다이어그램/박스를 그릴 때:
1. 확정폭 문자만 사용: 구조는 ASCII(+ - | > < v ^), 텍스트는 한글/영문.
   박스문자(┌─│└┘), 화살표(→←►◄↑↓), 원문자(①②), 기호(×·≥※) 금지
   — East Asian Ambiguous 폭이라 렌더러마다 1칸/2칸이 달라 정렬이 깨짐.
   대체: → 는 ->, ① 은 (1), × 는 x, ≥ 는 >=, · 는 . 로.
2. 폭 검증 없이 손으로 패딩을 맞추지 말 것 (3줄짜리 박스도 틀림).
   한글=2칸, ASCII=1칸으로 계산해 모든 박스 줄의 표시 폭이 동일한지
   Python(unicodedata.east_asian_width)으로 검증 후 출력할 것.
3. 여러 열의 가로 정렬이 복잡하면 세로 흐름으로 재구성할 것.
```
