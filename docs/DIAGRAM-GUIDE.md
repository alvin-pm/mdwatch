# ASCII 다이어그램 작성 가이드 — 깨지지 않는 박스 그리기

md 코드블록 안에 텍스트 다이어그램(박스·플로우)을 그릴 때 정렬이 깨지지 않게 하는 규칙입니다. **사람이 쓸 때도, AI 에이전트가 생성할 때도 동일하게 적용하세요.** (AI용 복붙 지시문은 [맨 아래](#ai-에이전트용-지시문-복붙용))

## 왜 깨지는가

**원인 1 — 문자 폭이 폰트마다 다름.**
박스 문자(`┌ ─ │`)·화살표(`→ ↑`)·원문자(`①`) 같은 특수문자는 유니코드 폭 분류가 "Ambiguous"라서, 같은 고정폭 폰트 계열 안에서도 폭이 갈립니다. 실측 예: D2Coding은 `─`를 1칸, Nanum Gothic Coding은 2칸으로 그립니다. 폰트가 글리프를 아예 안 가진 경우(예: NGC에는 `►` 없음)엔 시스템 폴백 폰트의 임의 폭으로 렌더링됩니다.

**원인 2 — 한글 폭이 영문의 정확히 2배가 아닌 폰트.**
일반 고정폭 폰트(SF Mono 등)에는 한글 글리프가 없어 비례폭 한글 폰트로 폴백되고, 그 폭은 영문 2칸과 미세하게 어긋납니다.

**mdwatch의 해결**: 코드블록 폰트를 **D2Coding으로 통일**합니다 — 로컬 설치본 우선, 미설치 환경은 D2Coding 웹폰트(CDN, 1.4MB 캐시)로 폴백. 그래서 mdwatch로 보는 문서에서는 아래 "mdwatch 문자셋"의 폭이 확정됩니다.

## 문자셋 2단계

### A. mdwatch 문자셋 — mdwatch로 보는 문서용 (권장)

D2Coding 실측 기준으로 폭이 확정된 문자들. 박스·화살표를 자연스럽게 쓸 수 있습니다.

| 폭 | 문자 |
|---|---|
| **1칸** | ASCII 전부 |
| **1칸** | 박스: `─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼ ═ ║` |
| **1칸** | 화살표: `→ ← ↑ ↓ ↔ ↕` / 삼각: `▲ ▼ ► ◄` / 도형: `◆ ● ○ ■ □` |
| **1칸** | 기호: `× · ≥ ≤ ※` |
| **2칸** | 한글, 원문자 `① ② ③` |

예시 (박스 줄 모두 18칸):

```
┌───── 박스 ─────┐
│ 한글 정렬 유지 │
└────────────────┘
   ↑ 세로 화살표도 OK
```

### B. 이식성 문자셋 — GitHub·VS Code 등 외부에서도 읽힐 문서용

mdwatch 밖의 뷰어는 폰트를 통제할 수 없으므로, 특수문자 폭이 다시 불확정이 됩니다. 외부 공개·공유가 예정된 문서는 **ASCII + 한글만** 사용하세요:

| 쓰지 말 것 | 대신 쓸 것 |
|---|---|
| `┌ ─ ┐ │ └ ┘` | `+ - \|` |
| `→ ← ↑ ↓` | `-> <- ^ v` |
| `① ② ③` | `(1) (2) (3)` |
| `× ≥ ·` | `x >= .` |

참고: 한글이 든 다이어그램은 어차피 GitHub 기본 폰트에서 2배폭이 보장되지 않으므로, 완전한 이식성이 필요하면 한글 없는 다이어그램 또는 Mermaid를 쓰는 것이 안전합니다.

## 폭 검증 — 필수, 크기 예외 없음

어느 문자셋을 쓰든, 한글·특수문자가 든 줄의 패딩을 눈대중이나 암산으로 맞추면 반드시 틀립니다 (3줄짜리 박스도 18/19/17칸으로 틀린 실제 사례가 있습니다). 반드시 스크립트로 검증하세요:

```python
import unicodedata

# mdwatch 문자셋 폭 테이블 (D2Coding 실측 기준)
WIDE = set('①②③')  # 2칸 특수문자 (한글은 자동 판정)
NARROW_SPECIAL = set('─│┌┐└┘├┤┬┴┼═║→←↑↓↔↕▲▼►◄◆●○■□×·≥≤※')  # 1칸 확정

def width(s):
    total = 0
    for c in s:
        if c in WIDE:
            total += 2
        elif c in NARROW_SPECIAL or ord(c) < 128:
            total += 1
        elif unicodedata.east_asian_width(c) in 'WF':  # 한글 등
            total += 2
        else:
            raise ValueError(f"폭 미확정 문자: {c!r} (U+{ord(c):04X}) — 표에 없는 문자는 쓰지 말 것")
    return total

# 박스의 모든 줄에 대해 width()가 동일해야 통과
lines = ["┌───── 박스 ─────┐", "│ 한글 정렬 유지 │", "└────────────────┘"]
assert len({width(l) for l in lines}) == 1, {l: width(l) for l in lines}
```

이식성 문자셋(B)으로 쓸 때는 `NARROW_SPECIAL`·`WIDE`에 걸리는 문자가 나오면 안 되므로, 해당 세트를 비우고 돌리면 됩니다.

## 복잡한 정렬은 구조를 바꿔라

여러 열을 가로로 맞추는 표 형태 다이어그램은 오류 확률이 열 수에 비례해 커집니다. 4열 플로우를 억지로 맞추기보다 **세로 흐름**(단계별 한 줄 + `│ ↓` 화살표)으로 재구성하는 것이 안정적이고 읽기도 좋습니다. 시각적 품질이 중요한 다이어그램은 **Mermaid**(mdwatch 기본 지원)가 정석입니다.

## AI 에이전트용 지시문 (복붙용)

Claude Code의 `CLAUDE.md`, Cursor rules 등 AI 설정 파일에 붙여넣으세요:

```text
md 코드블록에 텍스트 다이어그램/박스를 그릴 때:
1. 허용 문자만 사용 (mdwatch/D2Coding 기준 폭 확정 문자셋):
   - 1칸: ASCII, 박스문자 ─│┌┐└┘├┤┬┴┼═║, 화살표 →←↑↓↔↕,
     도형 ▲▼►◄◆●○■□, 기호 ×·≥≤※
   - 2칸: 한글, 원문자 ①②③
   - 이 표에 없는 특수문자는 쓰지 말 것.
   - GitHub 등 외부 공유용 문서라면 ASCII(+한글)만 사용:
     박스는 + - |, 화살표는 -> <- ^ v, 원문자는 (1)(2).
2. 폭 검증 없이 손으로 패딩을 맞추지 말 것 (3줄짜리 박스도 틀림).
   위 폭 테이블로 모든 박스 줄의 표시 폭이 동일한지 Python으로
   검증한 후 출력할 것.
3. 여러 열의 가로 정렬이 복잡하면 세로 흐름으로 재구성할 것.
```
